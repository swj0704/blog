오늘 앱에서 React Native를 걷어냈다. 정확히는 걷어내는 PR을 올렸다. 지운 줄 수는 3만 줄이 넘는다.

이 앱은 React Native 껍데기 위에 네이티브 화면을 얹은 구조였다. 화면을 하나씩 네이티브로 옮겨왔고, 마지막까지 남아 있던 게 탭이 달린 메인 화면이다. 오늘 그걸 옮겼고, 옮기고 나니 React Native가 할 일이 없어졌다.

## 마지막 화면이 마지막인 이유

메인 화면을 맨 뒤로 미룬 건 쪼갤 수 없어서다.

탭 화면은 push로 쌓이는 화면이 아니라, 한 화면 안에서 내용만 갈아 끼우는 구조다. 탭 하나만 네이티브로 옮기면 하단 바와 따로 논다. 하단 바와 모든 탭이 한 묶음으로 넘어와야 한다. 그래서 다른 화면을 전부 옮긴 뒤에야 손댈 수 있었다.

오전에 탭을 하나씩 넘겼다. 앱 변형이 하나 더 있어서 오후에는 그쪽 탭들도 넘겼다.

## 나란히 놓고 본다

옮긴 화면은 기기에 띄워서 React Native 화면과 나란히 봤다. 기능은 되는데 생김새가 달랐다. 숫자가 살짝 두꺼웠고, 간격이 조금씩 어긋났고, 카드 모양은 많이 달랐다.

기준은 하나로 정했다. React Native 화면에 최대한 맞춘다. 간격과 색은 원래 화면에서 잰 값으로 넣었다. 더 낫게 고치고 싶은 곳이 보여도 지금은 안 고친다. 옮기는 일과 고치는 일을 섞으면, 나중에 뭔가 달라졌을 때 어느 쪽 때문인지 알 수 없다.

이미 만들어둔 부품도 다시 찾아 썼다. 댓글 아이템이 새로 그려져 있길래 기존 것으로 바꿨고, 검색 아이콘도 다른 네이티브 화면이 쓰는 것으로 맞췄다.

## 화면만 옮기면 끝이 아니었다

React Native 메인 화면은 화면만 그리고 있던 게 아니었다. 보이지 않는 일을 여럿 하고 있었다.

- 앱을 닫을 때 리스너를 해제하고, 떠 있는 플레이어를 내리고, 진행 중인 통화를 끝내는 정리 작업
- 다른 화면에서 돌아올 때 특정 탭으로 옮겨주는 일. 네이티브가 JS로 이벤트를 보내면 JS가 탭을 바꾸는 식이었다.
- 특정 조건에서 띄우는 안내 팝업

화면을 옮겼다고 지우면 이런 것들이 조용히 사라진다. 크래시가 나지 않으니 한참 뒤에야 알게 된다. 지우기 전에 메인이 하던 일을 하나씩 찾아서 네이티브 쪽으로 옮겼다.

## 한 시간 동안 지웠다

지우는 건 바깥에서 안쪽 순서로, 커밋을 나눠서 했다.

1. **번역 문구를 한곳으로.** 언어팩 원본이 프로젝트 루트와 안드로이드 쪽에 따로 있고, 빌드할 때 복사하고 있었다. 안드로이드 쪽 하나로 합쳤다. 9,031줄 삭제.
2. **리소스 이름 정리.** 네이티브가 쓰고 있지만 이름은 React Native 번들 규칙을 따르던 이미지와 영상을 네이티브 이름으로 바꿨다. 파일 38개.
3. **안드로이드 코드에서 떼기.** React Native 메인, 브리지 모듈, 뷰 매니저를 지우고, JS로 보내던 이벤트를 없앴다. 3,233줄 삭제.
4. **Gradle에서 떼기.** React Native 플러그인, 자동 링크, node_modules 참조를 지웠다. 210줄 삭제.
5. **나머지 전부.** JS 소스, 도구 설정, 예전 번들 리소스를 지웠다. 파일 407개, 26,429줄 삭제.

첫 커밋이 오후 4시 12분, 마지막이 5시 16분이다. 몇 달에 걸쳐 화면을 옮겼는데, 지우는 데는 한 시간이 걸렸다.

순서를 이렇게 잡은 건 단계마다 빌드가 되는지 확인하려는 것이다. 한 커밋에 전부 지우면 빌드가 깨졌을 때 무엇 때문인지 찾을 수 없다. 화면을 옮기는 PR과 지우는 PR도 따로 올렸다. 지우는 쪽에 문제가 생기면 그것만 되돌리면 된다.

## CI에서도 빠졌다

마지막 커밋에서 CI 단계도 같이 지웠다. yarn 설치, 환경 파일 준비, JS 번들 만들기.

얼마 전 빌드 시간을 줄이는 글에서, 전체 태스크 1,078개 중 우리 코드에서 나오는 건 150개쯤이고 나머지는 의존하는 라이브러리 모듈이라고 썼다. 더 줄이려면 빌드 설정이 아니라 의존성을 덜어내야 한다고도 썼다. 그 의존성이 React Native였다. 오늘 덜어냈다.

빌드가 실제로 얼마나 빨라졌는지는 아직 재지 않았다.

## 남은 것

아직 머지 전이다. 눈으로 잡은 차이만 고쳤고, 나머지는 QA에서 나올 것이다.

그래도 저장소에서 JS 파일이 사라진 걸 보는 기분은 좋았다. 채팅 화면이 Fragment여야 했던 이유도, 빌드가 느렸던 이유도, 가드를 304개씩 달아야 했던 이유도 거슬러 올라가면 여기였다.
